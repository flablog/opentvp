# The .tvpp format (TVPaint Animation 11)

Reverse-engineered on TVPaint 11.7.6, from the `corpus/` files (generated by George scripts, with ground truth exported by TVPaint) and from production shots. Everything below is checked by the tests unless stated otherwise.

Conventions: big-endian integers; frames are numbered from 0 (the TVPaint timeline shows +1).

## 1. Section tree

The file is a tree of sections:

```
GUID (16 bytes) | size u64 BE | content (size bytes)
```

The section type is given by the first 4 bytes of the GUID:

| id | role |
|---|---|
| `3384780e` | root |
| `3385553a` | project header; key/value list at file offset 0x30 |
| `338631b2` | scene ("shot") |
| `3388da98` | scene header: `Drawings` (number of clips), `Name` |
| `3389b846` | clip |
| `3387e34a` | clip header (key/value) |
| `33871154` | clip body: IFF `FORM…TVPPXS24` |

**Key/value lists**: u32 number of pairs, then two strings per pair (u16 length in characters + UTF-16 BE).

- Project: `Width`, `Height`, `FrameRate`, `Camera.Width`, `Camera.Height`, `Camera.FrameRate`, `PixelAspectRatio`, `Author`, `LastChangeDate`…
- Clip: `Name`, `Hidden`, `MarkIn`, `MarkInPosition`, `MarkOut`, `MarkOutPosition`, `ColorIdx`, `Action`, `Dialog`, `Note`.

## 2. Clip body (IFF)

Chunks: 4-character ASCII tag + u32 BE size + content. An odd size may be followed by a padding byte.

At the start of the clip: `DGBL`, `DPEL`, `DLOC`, `BGMD` (8 bytes), `ARAT`, `CRLR`, `BGP1`/`BGP2` (RGBA background colours; different = checkerboard), `ANNO`, `FRAT` (fps × 1000), `FILD`, `MARK`, `XSHT`, `TLNT`.

Then, for each layer, top to bottom:

| chunk | content |
|---|---|
| `LNAM` | name (cp1252) |
| `LNAW` | name (UTF-8, takes precedence) |
| `LRHD` | layer header (104 bytes); `LRSH` = same structure, CTG layer |
| `DBOD` | first image (PackBits) |
| `SRAW` | one entry per following frame of the layer |
| `LRSR` | (CTG) start of the "result" series (computed fill), followed by the same `DBOD`/`SRAW` |
| `LEXT` | INI text: `[images auid]`, `[images name]`, CTG: `[scribbles source pos]` (0-based positions of the source layers), `[scribblescolors]`, `[scribblestextures]`, `[result images auid]`… |
| `UDAT`, `STCK`, `XSRC` | not used |

At the end of the clip: `FCFG`, clip INI (`[audio]`, `[cameradata]`, `[guideline]`, `[guiobjectcolors]`, `[info]`…). Project INI: `[guigroup]` (27 colour groups: names and colours).

### `ZCHK` compressed chunks (production files)

```
inner tag (4) | inner size (4) | "czmp" | u32 total size | u32 number of blocks
then for each block: u32 method (100 = zlib) | u32 raw size | u32 compressed size | data
```

Blocks are 64 KB. Once decompressed, you get the complete inner chunk (tag + size + content).

## 3. Layer header `LRHD`

| offset | type | field |
|---|---|---|
| 4 | u32 | first frame |
| 8 | u32 | last frame |
| 12 | u32 | number of frames (0 = image layer, visible from start to end) |
| 19 | u8 | opacity 0–255 |
| 28 | u32 | flags: bit 0 hidden, bit 4 locked |
| 44 | u16 | post-behaviour |
| 52 | u16 | pre-behaviour |
| 60 | u32 | blending mode |

Behaviours: 0 none, 1 repeat, 2 ping-pong, 3 hold. Repeat and ping-pong are anchored at the start of the layer, backwards as well.

Blending modes: 0 Color, 1 Behind, 2 Erase, 3 Shade, 4 Light, 5 Colorize, 6 Hue, 7 Add, 8 Sub, 9 Multiply, 10 Screen, 11 Replace, 12 Copy, 15 Difference, 16 Divide, 17 Overlay, 18 Light2, 19 Shade2, 20 HardLight, 21 SoftLight, 22 GrainExtract, 23 GrainMerge, 24 Sub2, 25 Darken, 26 Lighten, 27 Value, 28 Saturation.

## 4. Pixels

BGRA, premultiplied alpha.

**PackBits** (DBOD, tiles), row by row, on 4-byte pixels:
- n ≥ 128: repeat the next pixel 257 − n times;
- otherwise: n + 1 literal pixels.

**SRAW entries**: the first u32 gives the type.

| type | meaning |
|---|---|
| `0x40` | new image, tiled |
| `6` | hold: extends the previous image |
| `5` | new empty instance |
| `2` | new instance reusing the image of the layer frame given by the u32 at offset 4 (e.g. `00000002 00000021` → frame 33) |

There is one entry per frame of the layer's timeline. Layer frame 0 is the `DBOD` if there is one; otherwise it is the first `SRAW` entry, applied to an empty image.

**New image (0x40)**:

```
u32 type | u32 tile size (64) | u32 thumb_size | u16? thumbnail width, height
thumbnail: thumb_size − 8 bytes after the 16-byte header
u32 number of tiles
for each tile (64×64, partial on the right / bottom edge):
    u32 size > 0: PackBits tile
    u32 0: u32 source, u32 index  — source 1 = tile `index` of the previous image,
                                    source 0 = tile `index` of the current image
```

**CTG layers**: `LRSH` header. The main series holds the construction strokes; the computed fill is stored after `LRSR` (often without a `DBOD`: the result series starts from an empty image). Rendering uses the result series.

## 5. Camera (`[cameradata]` in `FCFG`)

Keys: `pathcount`, `mpoints-i-x`, `mpoints-i-y`, `mpoints-i-rotation`, `mpoints-i-zoomfactor`, `mmode`, `mmotionblur` (float, e.g. 0.5), `mprofile_prof_linear` (1 Linear, 0 Curve, 2 Polynomial), `mprofile_prof_numpoint`, `mprofile_prof_pointN` = "t p".

A new project has no points: the camera is then centred, at zoom 1.

**Framing** (continuous coordinates, y down, angle in degrees):

```
output − output_centre = R(+rotation) · (project − camera_centre) / zoom
```

The output size is `Camera.Width × Camera.Height`. A zoom > 1 shows a larger area (zoom out). Outside the canvas, the render is black.

**Time distribution between points**:
- For each segment i, Lᵢ is its x/y distance. With n segments: w₀ = L₀, wᵢ = (n − 1)·Lᵢ₋₁ + Lᵢ. If all weights are zero (zoom or rotation only), the weights are equal.
- Within a segment, x, y, rotation and zoom are interpolated linearly.

**Time**:
- N = extent of the visible layers (hidden layers and marks are ignored).
- Frame f → t = f / (N − 1), then u = profile(t).

**Profiles**:
- Linear.
- Curve: cubic Hermite, Catmull-Rom tangents `(y[i+1] − y[i−1]) / (x[i+1] − x[i−1])`, zero tangents at the ends. With two points, it is a straight line.
- Polynomial: Lagrange interpolation.

**Motion blur**: average of the framings over `[t, t + blur / (N − 1)]` (forward window).

**Known limitations**:
- Residual model error of ≤ 0.7 % of the movement compared to `tv_CameraInterpolation`.
- When `Camera.FrameRate` ≠ `FrameRate`, TVPaint resamples time at render; this is not modelled yet. It is the case for most files of the camera corpus (project at 24 fps, camera at 25 fps): this is the 3 to 8 % error that shows up in `tests/baseline_camera.json`. At 25/25 (N050_fps25, N117_fps25, N120_fps25), the error is zero.

## 6. Rendering

- In/out marks limit the rendered frames (inclusive).
- Background: `BGP1` on the canvas, black outside. If `BGP2` differs from `BGP1`, it is a checkerboard: the render uses `BGP1` and prints a warning.
- Visible layers, bottom to top, with their opacity and blending mode. Color is validated; Behind, Erase, Multiply, Screen, Add, Darken, Lighten, Difference and Overlay are implemented with the W3C formulas, but not yet validated against TVPaint.
- Resampling: bilinear, like Pillow, on premultiplied pixels.
- Straight alpha for export: rounding `(c × 510 + a) / (2a)`, identical to TVPaint's PNG export.

## 7. George pitfalls (to extend the corpus)

- `LOCAL`: variables separated by spaces, no commas.
- No expressions in command arguments: compute into a variable first.
- The main program must come before the `FUNCTION`s.
- Function arguments are split at commas, even inside quotes. `tv_WriteProjectString` fails with spaces or commas.
- `tv_LayerCreate` creates an image layer below the current layer (`tv_LayerAnim lid` turns it into an anim layer).
- Save with `tv_SaveProject`. To commit the last stroke: `tv_UpdateUndo`, then create and delete a temporary layer.
- A one-pixel `RectFill` draws nothing. `tv_LayerBlendingMode lid "Mode"` (without the id, the command is ignored).
- `tv_ProjectSaveSequence path "camera" start end` renders through the camera. TVPaint replaces digits in the file name with the frame number: use names without digits.
- `tv_CameraInsertPoint idx x y angle scale`. `tv_CameraInterpolation u` returns "x y angle scale" (use `PARSE result a b c d`).
- `tv_MarkIn n "set"`, `tv_MarkOut n "set"`, `tv_LayerDisplay lid "off"`, `tv_LayerLock lid "on"`, `tv_LayerPreBehavior` / `tv_LayerPostBehavior lid "repeat|pingpong|hold|none"`.
- `tv_ClipName` does not rename the first clip; `tv_ClipNew "name"` works.
- The scripts' output folder is set by the `base` variable at the top of the script, never hard-coded.

## 8. Sound (production file + `corpus/data/13_son`; offsets not confirmed yet)

- **Not embedded**: a `.tvpp` holds no audio data, only the path of each sound file. A file moved or renamed is lost to the project.
- **Two levels**: project tracks in the project INI section `04566928` (`[sound]`, then `[sound+N]`), clip tracks in the clip INI (`FCFG`, `[audio]`, then `[audio+N]`), N from 0. Each level has `trackcount`, `volume`, `mute`, `disclosed`, `annotation.count`. A clip without sound still has `[audio]` with `trackcount=0`.
- **One section per track**, same keys at both levels:
  - `filepath`: absolute path, as saved (Windows or Mac paths).
  - `offset`: start of the sound on the timeline, in seconds (0 = frame 0), rounded to 6 significant digits. TVPaint places the sound on a whole 48 kHz sample: B03, `offset=0.997917` (47900.016 samples), is exported 47900 samples late, to the sample. With a negative offset it cuts one sample too few from the start of the sound: B04, `offset=-0.219792` (−10550.016), is exported at −10549.
  - `volume`: linear gain (B01: 0.5 gives 0.4999 on the export). `mute`: 0/1; a muted track is left out of the mix.
  - `envelopein`, `envelopein2`: fade-in ramp, **linear in amplitude**, from 0 at `envelopein` to full at `envelopein2`, in seconds of the sound file (B05_fades_1s_keyframes: 0 → 0.513542, measured on TVPaint's export within 1 %).
  - `envelopeout`, `envelopeout2`: fade-out ramp, presumably from full at `envelopeout` to 0 at `envelopeout2`. Without a fade both hold the last sample time: (n − 1) / rate for 16-bit WAVs (3.99998 for 4 s), the duration for the 24-bit one (4).
  - `locked`, `coloridx`, `disclosed`, `annotation.count`: interface.
- **Mix** (TVPaint's movie export, AAC): the plain sum of the unmuted tracks (C01: tick × 0.998 + tone × 0.250 for volumes 1 and 0.25), each × `volume` × envelope; stereo kept as is (a right channel at half amplitude stays at half). 44.1 kHz mono and 24-bit sources load (A02, A03), their export is not measured yet. Sound starts on frame 0 (the AAC export adds its usual 1024-sample encoder delay).
- A **clip** exported alone (D02, each of its two 2 s clips; the 4 s sound is a project track) has **no audio stream**: project tracks are not exported with a clip.
- **Source formats**: the corpus uses WAV only. opentvp reads WAV itself and hands any other file to ffmpeg (first audio stream, at its own rate, then the same mix). ffmpeg removes the encoder delay of MP3 (LAME header) and AAC (MOV / MP4 edit list): a lag of 0 samples against the WAV source. Whether TVPaint does the same is not measured: a TVPaint export of a project using an MP3 or an AAC MOV would tell.
- **Project timeline** (assumed, not measured): the clips one after the other, in order, hidden ones included; a project track's offset counts from the start of clip 1. opentvp uses it for `--project-sound` and the player. A TVPaint export of the whole project with sound (D02) would confirm it.
- `[timelineaudio]` `soundpanelmode` is interface state.
- George: `tv_SoundClipNew path` / `tv_SoundProjectNew path` add a track; `tv_SoundClipAdjust idx mute volume …` / `tv_SoundProjectAdjust` set mute and volume, but the offset and fades given after them were ignored.
